## 1. 项目概述

### 1.1 项目背景

教师、学生、科研人员及知识工作者经常需要在本地保存课件、论文、制度文件、会议纪要和备课材料等文档，并围绕这些材料快速查找信息、整理答案和形成新的文档成果。现有的在线知识库、通用搜索或云盘方案通常存在资料分散、隐私顾虑、检索不精准、不能脱离浏览器使用等问题。

本项目拟开发一款 Windows / macOS / Linux 跨平台桌面应用，将“文档整理、向量化检索、图片信息读取、本地问答、内容整理”闭环集成于一个无需浏览器和命令行的图形化工具中。课件、论文、Word、PPT 等文档中的截图、图表、流程示意图等图片信息也应被知识库理解、检索和引用。文档资料默认保存在本机，只有调用云端大模型时才会按需发送必要的文本或图片内容，兼顾易用性、准确性与隐私安全。

### 1.2 项目目标

项目最终交付一个可安装运行、具备良好图形界面的本地文档知识库桌面助手，并达到以下目标：

1. 用户可以创建多个相互隔离的分类知识库，集中管理本地课件、论文、Word、PPT、TXT、Markdown 等资料。
2. 系统可自动完成文档解析、分块、向量化和入库，用户无需理解技术细节。
3. 用户可针对当前知识库进行多轮问答，答案基于本库文档内容并附带来源引用；资料不足以回答时明确提示，不编造内容。
4. 系统可读取上传文档内的图片信息：默认在本地提取嵌入图片并完成 OCR，必要时借助用户显式配置的视觉模型理解复杂图表，回答可引用“文档名、页码、图号”。
5. 对话结果可以生成或导出为规范的 Markdown 文档，便于整理笔记、形成讲义、沉淀研究材料并继续复用。
6. 支持自定义界面背景图片，使工具在保持内容清晰的前提下具备个性化外观。
7. 数据处理、存储和检索默认全部在本机完成，符合本地优先、隐私可控的原则。
8. 应用可打包为独立可执行程序，在未安装 Python 的同类操作系统电脑上直接运行。
9. 上传后的原始文档应显示在知识库侧栏中，用户点击即可在应用内阅读原文，并随时保存/导出原文副本。
10. 界面统一采用浅色二次元可爱风格，所有页面和对话框保持视觉一致，自定义背景图可全窗口覆盖且不影响文字阅读。
11. 支持在 DeepSeek、OpenAI、Moonshot、智谱等 OpenAI 兼容 AI 服务间切换，并在右上角显示当前 AI 与模型名称。
12. 数据存储目录可由用户自定义，文档、向量库、模型、背景图片等统一迁移到指定位置。
13. 在批量上传、大文档处理和多任务场景下保持界面响应，避免卡顿与任务堆叠。

### 1.3 目标用户与典型场景

| 目标用户 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 教师 / 课程设计者 | 按课程建立知识库，上传课件、讲义、教学大纲，向 AI 提问课程要点并导出教案或讲义 Markdown | 资料分类清晰、答案引用课件、生成文档可二次编辑 |
| 科研人员 / 研究生 | 建立论文资料库，上传 PDF 与论文笔记，围绕文献问答并整理综述提纲 | 本地保留全文、检索准确、可生成带引用来源的 Markdown 笔记 |
| 企业知识管理 / 行政人员 | 上传制度文件、流程说明、会议纪要，快速查询内部规范 | 私有资料不出本地、问答有据可查 |
| 普通知识用户 | 收集网页转存的 Markdown、TXT、Word 资料，搭建个人知识库 | 界面友好、可备份、跨平台使用 |

### 1.4 项目范围

#### 1.4.1 范围内

- 创建、删除、重命名、切换多个知识库。
- 上传并管理 PDF、DOCX、PPTX、TXT、Markdown 等常用文本文档。
- 从 PDF、DOCX、PPTX 等文档中提取嵌入图片，识别图片文字，形成可检索、可引用的图片上下文。
- 本地解析、分块、向量化、持久化存储。
- 基于知识库的多轮对话问答、流式输出、引用来源展示。
- 对话历史管理、Markdown 渲染、Markdown 文档生成与导出。
- 全局及知识库级自定义背景图片。
- Obsidian 风格知识库文件侧栏、文档原文阅读器与原文另存为。
- 可配置的 OpenAI 兼容多模态视觉理解服务（可选，默认关闭）。
- 多 AI 供应商切换、当前模型名称显示、自定义数据存储路径、统一浅色二次元主题。
- DeepSeek API Key、模型、检索参数等应用设置。
- 数据备份、导入导出与打包发布能力。

#### 1.4.2 范围外（V1.0 不作为必须交付）

- 复杂版式扫描件的逐页高精度版面还原（V1 不承诺；嵌入图片提取与 OCR 属于范围内）。
- 网页知识库抓取与在线同步。
- 多用户账号、云端数据库和协同编辑。
- 语音对话、视频/音频内容理解。
- 商业级组织权限管理和审计系统。
- 使用其他本地大模型或混合推理框架（除本地 OCR 与本地嵌入模型外）。

### 1.5 名词术语

| 术语 | 说明 |
| --- | --- |
| 知识库 | 用户创建的一组文档集合，拥有独立的数据、向量和对话空间 |
| 分块 / Chunk | 将长文档按语义或长度切分的检索单元 |
| 向量化 | 使用本地嵌入模型将文本转换为语义向量 |
| 向量检索 | 根据问题语义从向量库中查找最相关文本片段 |
| RAG | 检索增强生成，先检索相关资料，再由大模型组织回答 |
| 引用来源 | 回答中标注的文档名、页码、块序号等可追溯信息 |
| OCR | 光学字符识别，从图片中提取可检索文字 |
| 图片上下文块 | 由图片的 OCR 文本、语义描述、所在段落、图题与图号组成的检索单元 |
| 视觉模型 | 支持输入图片的 OpenAI 兼容多模态模型，用于理解图表、示意图等视觉语义 |

### 1.6 设计约束与非功能要求

- 跨平台：Windows 10/11、macOS、主流 Linux 桌面发行版均可运行。
- 本地优先：文档解析、OCR、向量化默认在本机完成；只有用户显式配置的 DeepSeek API 或可选视觉 API 参与云端推理时才发送必要内容。
- 数据隔离：不同知识库的文档、向量、对话和外观设置互不串扰。
- 易用性：全程图形界面，无命令行走查。
- 可打包性：通过 PyInstaller 生成当前平台独立可执行文件。
- 中文支持：界面、检索和导出文档默认以中文为主，编码统一使用 UTF-8。

## 3. 技术选型

| 模块 | 技术 | 说明 |

## 4. 系统架构

### 4.1 总体架构

应用采用单进程、分层模块化的桌面架构。GUI 层只负责展示与交互，耗时任务通过线程池或 QThread 执行，核心逻辑层与数据层负责业务规则和持久化。

```text
┌────────────────────────────────────────────────────────────┐
│                     桌面应用（单进程）                        │
│                                                            │
│  ┌────────────┐       ┌───────────────────────────┐        │
│  │  GUI 层     │  ←→   │  核心逻辑层                │        │
│  │ (PySide6)  │       │  - 知识库 / 文档服务        │        │
│  │            │       │  - 解析与分块               │        │
│  │ 主窗口      │       │  - 向量检索与问答           │        │
│  │ 知识库面板  │       │  - Markdown 文档服务        │        │
│  │ 文档管理    │       │  - 背景与主题服务           │        │
│  │ 聊天区      │       │  - LLM / 流式调用          │        │
│  │ 设置窗口    │       └────────────┬──────────────┘        │
│  └────────────┘                      │                       │
│                        ┌─────────────▼──────────────┐       │
│                        │        数据层                │       │
│                        │  SQLite：元数据/会话/设置     │       │
│                        │  Chroma：知识库向量集合       │       │
│                        │  文件系统：原始文档/MD/背景图  │       │
│                        └─────────────────────────────┘       │
│                                                            │
│  外部依赖：DeepSeek API（仅在配置后发送检索片段）             │
└────────────────────────────────────────────────────────────┘
```

### 4.3 数据与隐私边界

- 原始文件：仅保存到用户本机数据目录。
- 解析文本：保存在 SQLite 缓存或 Chroma 块元数据中，用于本地检索。
- 向量与索引：保存在本机 Chroma 目录。
- 从文档中提取的媒体图片：保存在各知识库媒体目录，用于 OCR、视觉理解与来源展示。
- 对话与导出文档：保存在本机 SQLite 与用户指定目录。
- 背景图片：仅作为界面资源使用，不进入文档解析、向量检索或模型上下文。
- 文本大模型调用：只发送“当前问题 + 检索片段 + 提示词”，不发送完整原文和本地文件路径。
- 图片与隐私：本地 OCR 默认开启且不联网；视觉理解默认关闭，只有用户在设置中显式配置并允许后，才会把命中的相关图片发送到指定视觉服务。

## 5. 功能需求详细说明

### 5.1 知识库管理

需求编号：KB-01 ~ KB-04

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| KB-01 | 创建知识库 | 输入名称（必填，限制长度）和描述（可选）；重名校验；创建后自动切换到新库 |
| KB-02 | 删除知识库 | 二次确认后删除知识库元数据、原始文件、向量集合与对话记录；可提示“删除前是否导出/备份” |

界面要求：

- 左侧固定或可折叠的知识库列表，显示名称、文档数、最近更新时间。
- 删除不可恢复操作必须使用确认对话框。
- 文档处理、向量化期间禁止删除当前文档所在知识库；若确有删除请求，先提示“有任务进行中”。

### 5.2 文档管理

需求编号：DOC-01 ~ DOC-06

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| DOC-01 | 上传文档 | 支持多选；文件类型为 .pdf、.docx、.pptx、.txt、.md；可设置拖拽上传 |
| DOC-02 | 文件复制入库 | 原始文件复制到当前知识库文件目录，按上传时间避免同名冲突 |
| DOC-03 | 文档列表 | 显示文件名、类型、大小、上传时间、处理状态、失败原因 |
| DOC-04 | 删除文档 | 从列表中移除文档及其分块向量；可保留原始文件到回收站或彻底删除 |
| DOC-05 | 重新处理 | 对失败或用户主动修改后的文档重新执行解析、分块、入库 |
| DOC-06 | 任务反馈 | 解析进度、当前步骤、错误原因实时反馈到界面，不阻塞交互 |
| DOC-07 | 图片资料（可选） | 支持将 JPG/PNG/BMP/WebP 等图片直接作为知识库资料上传；上传后按图片资料流程处理并检索 |

附加要求：

- 上传前做扩展名、文件大小和文件可读性校验，并给出明确中文提示。
- 文档状态至少包含：等待中、解析中、向量化中、成功、失败。
- 文档包含图片时，处理状态可展开显示“提取图片中 / OCR 中 / 视觉理解中”等子步骤。
- 应用异常退出后，重启时可将“解析中”状态修正为“失败/待重试”，避免假状态。
- 知识库中应保留可维护的“原始文档目录”与“生成文档目录”，用户可看到并备份。

### 5.3 文档解析与向量化

需求编号：ING-01 ~ ING-05

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| ING-01 | 格式解析 | PDF、Word、PPT、TXT、Markdown 均提取纯文本；PDF/PPT 尽量保留页/页索引 |
| ING-02 | 文本分块 | 按字符/语义窗口分块，默认 chunk_size=500 tokens、overlap=50 tokens，块数可配置 |
| ING-03 | 本地嵌入 | 使用 bge-small-zh-v1.5 生成向量，离线运行；可设置仅 CPU |
| ING-04 | 向量入库 | 每条块包含文本、文件 ID、文件名称、页码/幻灯片、块序号等元数据 |
| ING-05 | 增量与重处理 | 文档更新时先删除旧块再重建，保证没有重复向量和过期片段 |

注意事项：

- 解析失败的文件不应中断整批任务，应在列表中单独标记失败原因。
- 对超大文件或复杂 PDF 设置超时与内存保护。
- 向量集合名称与知识库 ID 关联，但集合本身不展示给普通用户。

### 5.4 文档图片信息读取

需求编号：IMG-01 ~ IMG-09

说明：DeepSeek 的常规 Chat API 以文本为主，不能直接“看图”。因此系统采用两阶段方案保证知识库可阅读图片：第一阶段默认使用本地图片提取 + OCR，把图片内容转成可检索、可引用的文本；第二阶段提供可配置的 OpenAI 兼容多模态视觉模型，对复杂图表、流程图和示意图进行语义理解。两种能力都以“图片上下文块”方式进入知识库。

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| IMG-01 | 嵌入图片提取 | PDF/DOCX/PPTX 解析时提取文档内图片，记录页码/幻灯片号、图题、相对位置并保存到知识库媒体目录 |
| IMG-02 | 本地 OCR | 默认使用 RapidOCR 本地识别图片文字，支持中文、英文、数字；OCR 过程不联网 |
| IMG-03 | 图片上下文块 | 将图片 OCR 文本、可选语义描述与所在段落、图题、图号组合成分块，向量化后进入当前知识库 |
| IMG-04 | 可选视觉理解 | 用户配置并启用视觉模型后，对图表、流程、示意图生成结构化描述，包括图类型、坐标轴、趋势、结论要点 |
| IMG-05 | 图片级引用 | 回答引用时显示“文档名 第X页 图N”；聊天区可查看图片缩略图并放大原图 |
| IMG-06 | 图片问答降级 | 未启用视觉模型且图片无有效文字时，明确提示“当前资料包含图片，请启用视觉理解或查看原图”，不编造内容 |
| IMG-07 | 直接图片资料 | 直接上传的图片按独立图片文档处理，保存媒体文件并建立图片上下文（优先级 P2） |
| IMG-08 | 失败与重试 | 损坏图片、超大图片、OCR/视觉理解失败可单独标记，不中断整篇文档处理 |
| IMG-09 | 数据清理 | 删除文档或知识库时，同步删除其媒体文件、图片向量和引用记录 |

行为与界面要求：

- 文档处理完成后可查看每张图片的处理结果：原始图片、页码/图号、OCR 文本、语义描述、状态。
- 图片内容只属于所在知识库；不同知识库之间的图片资料严格隔离。
- 图片上下文块在 Markdown 导出时保留为图片引用与来源说明。
- 可选视觉模型默认关闭；开启时设置界面必须明确提示“图片将发送至你配置的第三方服务”。
- 页面含图片时上传前显示预计处理项，用户可选择“跳过图片理解，仅索引文字”。

### 5.5 对话问答

需求编号：QA-01 ~ QA-08

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| QA-01 | 新建/继续会话 | 每个知识库可拥有多个会话；会话显示标题与创建时间 |
| QA-02 | 多轮问答 | 上下文包含本会话历史，但始终优先使用当前知识库检索结果 |

| QA-05 | 无法回答提示 | 检索结果不足或低于阈值时显示“根据已有文档，无法回答该问题” |

- 输入框支持 Enter 发送、Shift+Enter 换行，长内容不遮挡按钮。
- 发送按钮在“正在生成”时应切换为“停止”状态。
- 流式生成过程中保留引用标记原文，不将 Markdown 语法误识别为用户可见字符。
- 若答案来自图片上下文块，聊天区显示图片缩略图、页码/图号及“查看原图”操作。

### 5.6 对话生成与导出 Markdown 文档

本版本将 Markdown 作为应用的标准“可编辑成果格式”，同时支持“记录导出”和“内容生成”两种用途。

#### 5.6.1 功能范围

需求编号：MD-01 ~ MD-07

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| MD-01 | 回答即 Markdown | 聊天区原生渲染 Markdown，提供“复制 Markdown 原文”按钮 |
| MD-02 | 导出会话记录 | 将当前会话或所选消息导出为对话记录型 Markdown |
| MD-03 | 生成知识文档 | 基于当前对话和检索片段，由 AI 整理生成结构化 Markdown 文档 |
| MD-04 | 文件命名 | 默认按“知识库名_主题/日期”命名，非法字符自动清理，支持重命名与防覆盖确认 |
| MD-05 | 元信息 | 文件开头写入 YAML front matter：标题、知识库、创建时间、模型、来源文档 |

#### 5.6.2 记录导出型格式

```markdown
source_documents:
  - 课件_第03章_神经网络.pdf
---

# 对话记录

## 问：什么是反向传播？

反向传播是……[来源：课件_第03章_神经网络.pdf 第12页]

## 问：有哪些改进方法？

……
```

#### 5.6.3 AI 生成文档型格式

适用于形成讲义、总结、研究笔记等正式内容：

```markdown
---
title: 反向传播原理总结
knowledge_base: 机器学习课程
created_at: 2026-09-04 10:35
model: deepseek-chat
source_documents:
  - 课件_第03章_神经网络.pdf
tags:
  - 神经网络
---

# 反向传播原理总结

## 摘要

## 一、核心概念

## 二、推导过程

## 三、典型问题与改进

## 四、参考资料
```

生成策略：

- 生成前必须沿用防幻觉约束：只整理检索片段和当前对话中已有内容。
- 可提供“摘要式”“讲义式”“笔记式”模板，用户选择后由 AI 填充正文。
- 正文中的事实性关键句尽可能保留引用标记，格式如 `[1] 课件_第03章_神经网络.pdf 第12页`。
- 生成完成前不自动写入最终文件，先展示预览；用户确认后再保存。
- 生成失败时保留对话内容，允许直接以记录导出型保存。

#### 5.6.4 导出对话框

导出对话框至少包含：

- 导出类型：对话记录 / AI 生成知识文档 / 当前回答。
- 范围：全部消息 / 仅 AI 回答 / 从第 N 条到第 M 条。
- 是否包含引用来源附录、是否加入当前知识库。
- 文件名预览、目标目录选择、覆盖确认。
- 成功后显示“打开所在文件夹”“复制路径”“再次导出”操作。

| SYS-12 | PDF 交互 | 鼠标滚轮切换 PDF 页，Ctrl+滚轮缩放，缩放倍率真实改变页面尺寸 |
| SYS-13 | 按钮动效 | 悬停、按下、释放时使用短时阴影过渡，保持布局稳定 |
| SYS-14 | 空索引保护 | 没有已索引内容时不加载嵌入模型、不发送 AI 请求，并提示上传/处理文档 |
| SYS-15 | 智能问答入口 | 文本选中后右键可询问 AI；PDF 可对当前页询问，结果在侧栏展开 |

交互要求：

- 所有页面使用同一套全局样式变量和组件样式，不允许局部页面使用不同主题。
- 背景文件与当前数据目录相同路径时不重复复制。
- 更改存储目录后明确提示重启，应用启动时优先读取用户自定义路径。
- AI 供应商切换后自动填充默认 Base URL 和模型，支持手动修改。

## 7. 核心流程

### 7.1 文档入库流程

```text
用户选择文件
  → 校验格式、大小、可读性
  → 复制到当前知识库文档目录
  → 创建 Document 记录（状态：解析中）
  → 调用解析器提取纯文本与页码信息
  → 提取 PDF/DOCX/PPTX 中的嵌入图片，保存到 media/
  → 图片本地 OCR；若启用视觉理解，再生成语义描述
  → 将 OCR/描述与图题、正文组合为图片上下文块
  → 按参数分块
  → 本地嵌入模型向量化
  → 写入当前知识库 Chroma 集合
  → 更新状态为“成功”
  → 失败时记录 error_message，状态为“失败”
```

要点：

- 单文件或整批任务均可取消，取消后已入库数据保留为“成功”，未处理文件可手动重试。
- 文档列表提供“停止”“重试”“删除”等操作。
- 图片处理失败不影响正文入库；该图片单独标记失败并支持重试。

### 7.2 文档图片信息读取流程

```text
解析文档
  → 定位图片对象及所在页/幻灯片/图题
  → 解码并校验图片（损坏/超大/非图像）
  → 保存原始图片到当前知识库 media/ 目录
  → 执行本地 OCR，得到可检索文字
  → 若用户启用视觉模型：对图表生成结构化语义描述
  → 写入 media_assets（OCR、描述、图号、状态）
  → 图片上下文块向量化入库
```

问答侧的处理策略：

```text
用户提问
  → 向量检索命中图片上下文块
  → 默认把 OCR 文本与描述作为资料回答，并引用“文档名 第X页 图N”
  → 视觉模型已启用且检索到相关图片时：仅发送相关原图与问题
  → 模型无法给出可信答案时，提示查看原图，不编造
```

### 7.3 问答流程

```text
用户提问
  → 获取当前知识库 ID 与会话
  → 向量化问题
  → Chroma 检索 Top-K，按阈值过滤
  → 结果不足：返回“根据已有文档，无法回答该问题”
  → 构建系统提示 + 检索片段 + 历史 + 问题
  → DeepSeek 流式生成
  → 解析 Markdown 与引用标记
  → 保存消息与会话
  → 前端展示答案与来源
```

### 7.4 Markdown 生成/导出流程

```text
用户在聊天区选择“生成或导出 Markdown”
  → 选择类型：记录导出 / AI 生成文档 / 当前回答
  → 选择消息范围与模板
  → 若为 AI 生成：调用问答服务生成预览
  → 预览确认
  → 校验文件名为合法 UTF-8 文件名
  → 写入 YAML front matter 与正文
  → 可选：复制到 knowledge base 并触发自动入库
  → 记录 markdown_exports
  → 提示打开文件或所在目录
```

### 7.5 自定义背景流程

```text
用户在设置中选择背景图片
  → 校验格式、大小、损坏情况
  → 复制到 backgrounds/ 目录
  → 保存作用范围（全局/KB）、显示模式、蒙层参数
  → 工作线程加载并缩放图片
  → 主界面刷新背景层
  → 重启时读取设置并恢复
  → 文件缺失/损坏时自动回退默认外观
```

### 7.6 防幻觉与质量措施

1. 系统提示词明确要求：“只依据提供的资料回答，不编造；若资料中没有答案，请回答‘根据已有文档，无法回答该问题’。”
2. 相似度阈值默认 0.6，低于阈值的片段不送入模型。
3. 引用以 `[来源] 文档名 第X页` 或 `[1] 文档名 第X页` 形式附在答案中。
4. 对检索片段做长度截断，防止上下文超限。
5. 对模型输出做后处理：清理空回答、校验引用来源是否出现在检索片段中。
6. Markdown 导出内容默认附加“本文件由 AI 辅助生成，请以原始文档为准”的可选提示。
7. 图片类回答只使用检索到的 OCR 文本、语义描述或发送给视觉模型的相关原图；未获得可信信息时提示查看原图，不编造。

## 10. 风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| PyInstaller 与 Chroma/sentence-transformers 兼容问题 | 打包体积大、运行时报缺库 | 使用 onedir 模式，必要时补充 hidden-import/collect-all；提前在干净环境回归 |
| 嵌入模型包体积大、首次加载慢 | 安装包大、启动慢 | 采用 bge-small-zh；启动时懒加载；显示加载进度 |
| RapidOCR 对复杂图表/低清晰图片识别不准 | 图片内容理解不完整 | OCR 作为基础层，启用可选视觉模型生成语义描述；界面显示识别置信度或失败原因 |
| DeepSeek 文本接口无法直接理解图片 | 用户问图表趋势时回答不完整 | 默认将图片转 OCR/描述文本；提供 OpenAI 兼容视觉模型；当前模式下明确提示 |
| 可选视觉模型泄露图片隐私 | 用户敏感图片发送到第三方 | 默认关闭；设置中显式配置、发送前授权、只发送检索命中的相关图片，并记录发送日志 |
| OCR/onnxruntime 增加打包体积 | 安装包偏大 | 采用轻量模型并按需提供可选组件；README 说明磁盘空间需求 |
| PDF 版式复杂或纯扫描件解析难 | 入库失败或文本缺失 | 文本型 PDF 直接提取；嵌入图片走 OCR；纯扫描件整页 OCR 列入后续增强 |
| 检索召回不准 | 回答错误 | 调整分块参数与阈值，提供 Top-K 调参；测试集回归 |
| DeepSeek 不可用/限流 | 提问失败 | 错误分类与重试；网络恢复后自动可继续；不阻塞文档管理 |
| 用户误删数据 | 数据丢失 | 删除确认、回收站式文档删除、本地备份提示 |
| 背景图片降低可读性 | 界面体验受损 | 默认蒙层、面板不透明度、重置按钮，验收保证文字清晰 |
| Markdown 渲染含危险 HTML | 本地安全风险 | 默认关闭或转义 HTML，仅渲染安全 Markdown 子集 |
| 跨平台路径/字体差异 | 显示异常 | 使用 pathlib 统一路径；按操作系统选择默认字体并做中文字体兼容 |
